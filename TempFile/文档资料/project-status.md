# 灵月桌面 项目进展

> 最后更新：2026-09-04
> 版本：1.1.11（多显示器稳定布局本地更新版）

## 技术栈

| 层       | 技术                                                             |
| -------- | ---------------------------------------------------------------- |
| 框架     | Electron 39 + electron-vite 5                                    |
| 前端     | React 19 + TypeScript 5.9                                        |
| 样式     | Tailwind CSS v4 + Shadcn/UI                                      |
| 状态管理 | Zustand 5                                                        |
| 动画     | Framer Motion 12                                                 |
| 存储     | electron-store 8（`%APPDATA%/lingyue-desk/lingyue-config.json`）+ userData 运行时覆盖层 |
| 壁纸嵌入 | electron-as-wallpaper 1.0.4（仅 Windows）                        |
| AI 伴侣/轻量助手 | Vercel AI SDK v6 + SQLite/Drizzle + better-sqlite3 + 声明式组件协议 |

## 架构概览

```
┌─────────────┐  ┌──────────────┐  ┌──────────────┐
│  主界面窗口  │  │  壁纸窗口     │  │  组件画布窗口 │
│  main-ui    │  │  wallpaper   │  │  canvas      │
│  设置/管理   │  │  贴合桌面     │  │  透明层       │
└──────┬──────┘  └──────┬───────┘  └──────┬───────┘
       │                │                  │
       └────────── IPC (preload) ──────────┘
                        │
                ┌───────┴────────┐
                │    主进程 main   │
                │  窗口/托盘/存储  │
                └────────────────┘
```

四类窗口设计：主界面（设置）、每显示器一个壁纸窗口（贴合桌面）、单一组件画布（透明覆盖层）、系统托盘。

## 已知问题与经验

| 问题                              | 根因                                        | 解决方案                       |
| --------------------------------- | ------------------------------------------- | ------------------------------ |
| vvhan.com API 失效                | 域名不可用                                  | 替换为 codelife.cc + weibo.com |
| 切壁纸组件不刷新                  | catch 分支未清空 + 未 cancelPendingAutoSave | 补齐清空逻辑                   |
| 6 个 IPC 通道未定义               | 遗漏                                        | 补齐 ipc-channels.ts           |
| Electron acrylic 无法采样嵌入壁纸 | 系统限制                                    | 改用壁纸抽帧广播 + CSS blur    |
| `.lnk/.url` 启动不稳定            | 直接 spawn 快捷方式目标不等同桌面双击行为  | 优先交给 Windows Shell 打开原快捷方式 |
| DeepSeek thinking 模型工具续聊失败 | OpenAI 兼容适配会丢 `reasoning_content`      | 使用 DeepSeek 专用工具循环并回传 reasoning 内容 |
| 工具过程 UI 顺序混乱              | 模型文本和工具事件只按单次切分展示           | 按 `textOffset` 构建对话/工具交错时间线 |
| AI 模块定位偏重编程 Agent          | 文档一度按 Codex 式本地工作区 Agent 设计      | 已调整为 AI 伴侣优先；复杂文件回滚/审批不再是主线 |
| 打包后写入内置资源不可靠           | `resources/assets` 随安装包分发，应视为只读    | 壁纸导入、壁纸设置和组件覆盖配置改写到 userData；内置资源只提供默认值 |
| 在线壁纸不能信任远程 ZIP            | ZIP 可能损坏、越界或被替换                    | 限制 HTTPS/2 GiB，校验声明大小与 SHA-256，拒绝符号链接和越界路径后原子安装 |
| 打包后主界面白屏                   | sandbox preload 被 Rollup 拆出本地共享 chunk  | 单入口打包三套 bridge，并按窗口启动参数只暴露对应 API |
| 多显示器模式保存后不生效           | 模式读写和 renderer 布局被硬编码成 `per-display`，应用壁纸又总是传显示器 id | 恢复持久化模式为单一事实源，仅按屏模式使用显示器目标；复制/延展应用时保留当前布局 |
| 多屏壁纸跨屏错位、组件切模式跳动   | `SetParent` 后仍把 Electron 绝对 DIP 坐标传给桌面子窗口；壁纸分配依赖临时 display id；组件长期保存虚拟 Canvas 坐标；抽帧只接受主窗口 | 使用 Win32 物理边界和父级本地坐标定位并校验；按设备名持久化；组件改为显示器本地坐标；每显示器独立窗口、延展裁切和逐屏抽帧 |
| 更新错误泄露响应头                 | `electron-updater` 原始错误包含 headers/cookie | 主进程统一映射为脱敏、限长的用户提示并关闭原始 updater logger |
| 开机长时间锁屏后便利贴无法点击      | 透明 Canvas 在启动遮挡期间完成初始化，回到桌面后 renderer 丢失 `pointerdown` | 启动期长遮挡返回后重建 Canvas，并在原生按下无 renderer 回执时自动恢复 |
