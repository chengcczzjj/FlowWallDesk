> 对齐日期：2026-09-05；按现有代码整理。本文负责架构和数据边界；任务优先级见 [项目状态](../project-status.md)，通用协作规则见 [AGENTS.md](../../../AGENTS.md)。早期“先初始化工程、再做壁纸”的搭建顺序已不适用。

## 产品与进程边界

Windows 桌面 AI 伴侣：壁纸、桌面组件、陪伴式对话与桌宠为主线；本地工作区 Agent 为高级辅助。技术版本查 [package.json](../../../package.json)，不要根据旧技术方案重新初始化或更换当前工程。

| 运行部分 | 职责与限制 | 实现入口 |
| --- | --- | --- |
| 主窗口 main-ui | 设置、壁纸库、组件管理、聊天、宠物配置 | [mainWindow.ts](../../../src/main/windows/mainWindow.ts) |
| 壁纸窗口 wallpaper | 按布局目标为每显示器建本地窗口；延展也用逐屏裁切，不建单个混合 DPI 跨屏壁纸窗口 | [wallpaperWindow.ts](../../../src/main/windows/wallpaperWindow.ts) |
| 组件画布 canvas | 一个透明 Canvas 承载组件，按当前布局覆盖桌面；不为每个组件创建 Electron 窗口 | [canvasWindow.ts](../../../src/main/windows/canvasWindow.ts) |
| 系统托盘 | 主窗口显示/隐藏与退出入口，不是 BrowserWindow | [tray.ts](../../../src/main/tray.ts) |
| 主进程服务 | 窗口、持久化、下载、更新、原生桌面交互和 AI 工具执行 | [main/index.ts](../../../src/main/index.ts) |

三类渲染入口通过 [preload/index.ts](../../../src/preload/index.ts) 的单一打包入口通信，按窗口角色只暴露对应 bridge；角色实现分别位于同目录。窗口保持 sandbox，不将渲染层输入当作可信指令。新增 IPC 同步通道、共享类型、对应角色 bridge 与主进程参数/来源校验。

## 桌面链路：不要只修 UI 状态

- 模式持久化是显示布局的事实来源：主屏、复制、按屏、延展不能被调用方硬编码覆盖。
- 显示器使用 Win32 设备键匹配 Electron 显示器；设备识别失败时关注降级诊断，不能只看 UI 是否列出了两块屏。
- Electron DIP、Win32 物理像素、桌面父窗口本地坐标、Canvas 虚拟坐标是不同空间。`SetParent` 后转换父级本地坐标并校验实际矩形，不能继续套顶层窗口定位逻辑。
- 组件保存显示器键与屏幕本地坐标；同步/拖动边界再映射 Canvas 坐标。主显示器当前壁纸是组件配置命名空间，图标收纳另有跨壁纸全局保存逻辑。
- 点击链路包括原生命中、前台归属、穿透门、renderer 回执与焦点；“DOM 能命中”不证明 Windows 已投递事件。恢复操作受场景和手势门禁约束，不能持续抬升 Canvas。
- 详细约束、已被替代的修法和测试入口见 [经验 L03-L08](../dev-lessons.md) 与 [多显示器方案](../../../doc/双显示器支持方案.md)。

## 运行时数据边界

打包后内置程序、asar 和 `resources/assets` 视为只读。用户调整不写回安装目录；[userDataPaths.ts](../../../src/main/runtime/userDataPaths.ts) 负责路径生成，业务代码不要自行拼接可能冲突的壁纸 ID。

下列 `userData` 表示 Electron `app.getPath('userData')` 的运行时目录，不是仓库文件夹；覆盖目录使用路径 helper 生成的安全段，不假定等于原始 ID。

| 内容 | 存储位置/规则 |
| --- | --- |
| 内置壁纸及默认配置 | `assets/wallpaper/<id>/`，随安装包分发 |
| 用户导入壁纸 | `userData/wallpapers/` |
| 在线下载壁纸 | `userData/remote-wallpapers/`，资源版本与应用版本独立 |
| 用户壁纸设置与组件配置 | `userData/wallpaper-overrides/` 下的 `settings.json` / `widget-config.json`；优先读取覆盖层，缺失再读默认 |
| 桌面图标托管 | `userData/desktop-icons/<widgetId>/`；导入/恢复需保护原文件 |
| AI 事件、记忆和工作区记录 | SQLite，入口为 [memory/db/paths.ts](../../../src/main/memory/db/paths.ts) 与 [schema.ts](../../../src/main/memory/db/schema.ts) |
| 原生桌面/更新诊断 | `userData/logs/`，路径与轮转见 [diagnosticLog.ts](../../../src/main/runtime/diagnosticLog.ts) |

应用 AI 自修复的设计边界仅包含受控运行时数据与未来受控扩展包；诊断 UI 尚待完善，不能把边界定义视为功能已实现。核心程序、preload、IPC、工具注册和内置资源由正式版本更新修复。开发智能体在用户授权下修改本仓库，与应用 AI 的运行时权限是两件事。

## 模块导航与验证

- UI 与组件：`src/renderer/main-ui/`、`src/renderer/widgets/`；共享声明式组件结构在 [generated-widget.ts](../../../src/shared/generated-widget.ts)，不要注入任意生成代码。
- AI 调用链：[chatService.ts](../../../src/main/memory/chat/chatService.ts) -> [contextPacker.ts](../../../src/main/memory/routing/contextPacker.ts) / [tools/index.ts](../../../src/main/memory/tools/index.ts)；记忆、检索、审批各守自己的边界。
- 资源下载：[wallpaper-resource-service.ts](../../../src/main/services/wallpaper-resource-service.ts) 与 [safe-zip.ts](../../../src/main/services/safe-zip.ts)；所有者发布校验在独立服务，不由 UI 隐藏按钮代替授权。
- 验证命令见根规则；测试目录含纯函数与源码契约检查，并非完整端到端测试。Windows 全屏/锁屏/远控、混合 DPI、多屏热插拔、打包安装必须分别注明实际验收情况。
