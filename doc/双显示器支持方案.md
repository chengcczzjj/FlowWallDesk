# 灵月双显示器支持方案

## 调研结论

本次实现参考了 Windows 壁纸应用的通用做法：

- **Lively Wallpaper** 的公开命令文档把多屏布局分为 `per`、`span`、`duplicate`：每台屏幕独立壁纸、跨虚拟桌面延展、所有屏幕复制同一壁纸；同时用 monitor id 做单屏设置。
- **Wallpaper Engine** 的桌面壁纸模型同样把“显示目标”和“壁纸内容”分开，跨屏模式按显示器几何边界裁切渲染，而不是把两个屏幕当作一个普通 DOM 屏幕。
- Windows 的显示器坐标可能出现负数（副屏在主屏左侧或上方），不能假设屏幕从 `(0, 0)` 开始；显示器热插拔、缩放、分辨率变化后需要重新计算虚拟桌面矩形。

因此灵月采用“**一个覆盖虚拟桌面的透明窗口 + 按显示器边界分区渲染**”方案：壁纸窗口和组件画布窗口共享虚拟桌面 DIP 坐标，壁纸 renderer 根据模式渲染一个或多个 surface，组件仍保留单画布以避免每个组件创建原生窗口。

## 设置模式

| 模式 | 行为 |
| --- | --- |
| 仅主显示器 | 兼容原有单显示器行为，窗口只覆盖主显示器 |
| 复制到每台显示器 | 每台显示器独立铺满当前壁纸（视频各自播放） |
| 每台显示器单独设置 | 设置页按 Electron display id 选择不同壁纸；未指定时回退当前壁纸 |
| 跨屏延展 | 壁纸按虚拟桌面联合矩形渲染，显示器只显示自己的矩形区域 |

## 边界与恢复

- 显示器坐标、工作区、缩放比例通过主进程 `screen.getAllDisplays()` 获取，设置页展示分辨率、缩放和坐标。
- 当副屏位于左侧/上方时，组件坐标原点会随虚拟桌面变化；主进程保存 `widgetCoordinateOrigin` 并在模式切换时迁移已保存坐标，避免组件跳屏。
- 窗口收到 `display-metrics-changed`、`display-added`、`display-removed` 后重新设置虚拟窗口 bounds，并通知 renderer 拉取最新布局。
- 全屏遮挡判断改为“所有显示器都被覆盖”才暂停整套壁纸抽帧；副屏上的全屏应用不会误伤主屏组件。
