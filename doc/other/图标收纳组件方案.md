# 桌面图标收纳与 Dock 实现说明

> 状态：已落地。当前包含纵向收纳、横向收纳、自适应收纳和桌面 Dock 四类组件。

## 功能概述

用户可以把桌面上的快捷方式、文件、文件夹或 URL 拖入图标收纳组件。来自桌面目录的原文件会移动到应用托管目录，组件保存图标元数据并在桌面透明画布中渲染；删除收纳组件时会把托管图标恢复回原桌面位置。非 Dock 收纳使用双击启动，Dock 使用单击启动并带启动弹跳。

Dock 额外内置四个固定系统按钮：设置、资源管理器、回收站、回到桌面。它们不进入用户图标列表，也不参与拖拽排序，但会跟普通 Dock 图标一样使用悬浮放大设置，并采用 Win11 风格的图标本体。

## 组件类型

| 类型 | 名称 | 说明 |
| ---- | ---- | ---- |
| `desktop-icons-box` | 纵向收纳 | 纵向滚动布局，适合高透明玻璃收纳盒 |
| `desktop-icons-horizontal` | 横向收纳 | 横向滚动布局，适合横向工具条式收纳 |
| `desktop-icons-adaptive` | 自适应收纳 | 根据数量自动行列，resize 后可记录手动列数 |
| `desktop-icons-dock` | 桌面 Dock | 悬浮放大、启动弹跳、长按排序、玻璃/梯形样式 |

## 核心流程

```
桌面图标拖入组件 → preload 获取真实文件路径 → 主进程解析/提取图标
→ 桌面来源文件安全移动到 userData 托管目录 → 写入组件 config.items
→ 画布同步渲染 → 点击时按 Explorer 行为启动
```

删除组件时：读取组件内 `items` → 将 `removedFromDesktop=true` 的托管文件移动回原桌面目录 → 清理托管目录 → 更新组件列表。

托管目录位于应用用户数据目录下的 `desktop-icons/<组件 id>/`。导入桌面文件或文件夹时只使用原子 `rename` 移入托管目录；移动失败时原文件会留在桌面，不再走“复制后删除源”的兜底路径。若移动已经成功但组件记录写入失败，会尝试把托管项回滚回桌面；只有极端的回滚失败才需要到主进程日志和托管目录继续排查。

## 关键实现

- 主进程：`src/main/ipc/desktopIconIpc.ts` 负责导入、图标提取、启动、刷新元数据和恢复。
- 渲染组件：`src/renderer/widgets/DesktopIcons/DesktopIcons.tsx` 负责收纳布局、Dock 交互、长按排序、系统按钮和外观。
- 画布：`src/renderer/canvas/Canvas.tsx` 负责图标收纳 resize、长按移动组件、隐藏名称后的紧凑度量和配置同步。
- 设置页：`src/renderer/main-ui/pages/WidgetsPage.tsx` 新增“图标收纳”子页，支持预览、添加、多实例数量和全部删除。
- 浮动工具栏：`src/renderer/widgets/FloatingToolbar.tsx` 提供收纳/Dock 外观设置，以及“应用到全部收纳”独立按钮。
- IPC：`src/shared/ipc-channels.ts`、`src/preload/canvas.ts`、`src/preload/main-ui.ts` 暴露图标导入/启动/刷新、设置页打开、资源管理器和回到桌面动作。

## 启动与恢复策略

- `.lnk` 和 `.url` 优先交给 Windows Shell 打开原快捷方式，行为更接近桌面双击；失败后再回退到解析出的目标路径。
- `.url` 会解析 `URL=` 并通过 `shell.openExternal` 打开。
- 普通文件、文件夹和可执行文件会优先 `shell.openPath`，必要时使用 Windows `start` 兜底。
- 图标收纳与 Dock 作为跨壁纸全局组件保存到 `globalIconWidgets`，普通组件仍保存在当前壁纸的 `widget-config.json`。

## 故障排查日志

这些日志只输出到开发/排查控制台，不会显示在桌面 UI，也不参与业务判断。后续让 AI 排查图标收纳或 Dock 问题时，优先检查以下位置：

- 渲染端 DevTools Console：查看拖拽导入、启动和右键菜单的前端结果。
	- `[desktop-icons] import skipped:` 某些拖入项被跳过的明细，例如回收站等 Shell 虚拟对象没有真实路径、文件夹被占用、权限不足、跨卷移动不支持或托管目录不可写。
	- `[desktop-icons] import failed:` 整次导入失败的前端错误。
	- `[desktop-icons] launch failed:` 图标启动失败。
	- `[desktop-icons] context menu action failed:` 图标右键菜单操作失败。
- 主进程终端或 Electron 启动日志：查看文件移动、恢复和回滚问题。
	- `[desktop-icons] rollback failed:` 图标已移入托管目录，但组件记录写入失败后的回滚也失败；需要检查托管目录和原桌面路径。
	- `[widget] desktop icon restore incomplete, keeping widget:` 删除非 Dock 收纳时部分图标恢复失败，组件会保留剩余记录，避免丢失追踪。
	- `[widget] desktop icon restore incomplete, removing widget:` 删除 Dock 时部分托管项恢复失败，记录会提示需要人工排查托管目录。

常见导入失败原因包括文件夹正在被占用、权限不足、OneDrive/云同步锁定、杀软拦截、跨磁盘卷移动或路径冲突。正常失败路径应保留桌面原文件；如果用户反馈文件不在桌面且组件里也没有记录，先看主进程是否出现 rollback 日志，再检查 `desktop-icons/<组件 id>/` 托管目录。
